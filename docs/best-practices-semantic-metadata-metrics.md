# 数仓 Agent 底座最佳实践：语义层 + 元数据 + 可信指标

> 数仓 Agent 要可信，靠的是一条信任链：**元数据（让 Agent 看得懂）→ 语义层（让 Agent 算得对）→ 可信指标（让 Agent 答得准）**。三者缺一不可。

---

## 一、语义层（Semantic Layer）—— 让 Agent "算得对"

**核心理念：指标定义下沉到建模层，而不是散落在 BI / SQL 里。**

最佳实践：

1. **Metrics as Code（指标即代码）**：用声明式 YAML 把指标定义在事实表上，纳入版本管理和 dbt 的依赖图，指标自动继承血缘。
2. **定义一次，处处消费**：把指标定义从 BI 层上移到建模层，自动处理 join，消除重复编码。
3. **拥抱开放标准，避免厂商锁定**：2025 年出现的 **Open Semantic Interchange (OSI)** 是关键进展——dbt Labs、Snowflake、Salesforce 等用厂商中立的 YAML 标准化语义层定义，以 MetricFlow 作为声明式规范。
4. **面向 Agent 设计**：让 Agent 能按名称请求一个指标、拿回经过验证的 SQL，并保证在任何地方返回同一个答案。

选型参考：

| 方案 | 适用 |
|---|---|
| **dbt MetricFlow** | 厂商中立、多数仓、适合已用 dbt 的团队 |
| **Snowflake Semantic Views / Databricks Metric Views** | 各自数仓内原生、性能好 |
| **Cube** | 独立语义层，适合多 BI/多消费端场景 |

---

## 二、元数据（Metadata）—— 让 Agent "看得懂"

**核心转变：元数据从"后台卫生工作"升级为"关键基础设施"。**

最佳实践：

1. **区分"目录"与"管理"**：数据目录是可搜索的"前门"；元数据管理是背后让这扇门保持准确、安全、新鲜的引擎。
2. **建设"主动元数据"（Active Metadata）**：实时流动、自动更新、反向写回，驱动数据发现、治理、质量与血缘。
3. **覆盖四类元数据**：技术元数据（schema、类型、来源）、业务元数据（业务定义）、操作元数据（质量规则、加工逻辑）、社交元数据（谁查过、查询日志）。
4. **"BI-Ready ≠ AI-Ready"**：给人看够用的元数据，喂给 Agent 往往不够，需面向机器消费重新设计目录。
5. **落地节奏**：常用 90 天 rollout——分阶段编目、补语义、接血缘、定 KPI。

---

## 三、可信指标（Trusted / Certified Metrics）—— 让 Agent "答得准"

**核心理念：单一事实源（SSoT）= 一个定义 + 一套计算逻辑 + 一个受治理的存放地。**

最佳实践：

1. **正确理解 SSoT**：不是"一个数仓装所有数据"，也不是"没人执行的 wiki"；逻辑必须活在受治理的系统里。
2. **指标认证机制（Certify / Promote）**：对关键指标做官方认证，消除歧义。
3. **为 AI 认证资产**：确保 Agent 用的是约定口径（如 GMV、DAU、转化率）。
4. **统一给人和 Agent 用同一层**：让一个指标无论人问还是 Agent 问都一个意思。
5. **配齐治理三要素**：明确 owner、统一定义、选定单一源。

---

## 四、把三块串成落地路径

| 步骤 | 做什么 | 产出 |
|---|---|---|
| 1. 元数据先行 | 编目核心资产 + 补血缘 + 标 owner/质量状态，做成"主动元数据" | AI 看得懂的目录 |
| 2. 建语义层 | 用 YAML（MetricFlow/OSI 标准）把指标定义在事实表上，纳入版本管理 | 可被 Agent 按名调用的指标 |
| 3. 认证可信指标 | 对核心 KPI 做 certify，确立单一源 + owner | 人和 Agent 共用的口径 |
| 4. 接入 Agent | 让数仓 Agent 通过 MCP / Semantic Layer API 按名取指标、拿验证过的 SQL | 可信的数仓 Agent |

---

## 五、电商 / 消费者数据域的实操要点

- 电商指标多且口径复杂（GMV、转化、人群、流量口径），**最该先做"指标认证 + 单一源"**，否则 Agent 接进来一定算错账。
- 若团队已用类 dbt 工程化栈，**MetricFlow + OSI 标准**是最稳妥路线，既面向 Agent 设计，又避免厂商锁定。
- "BI-Ready ≠ AI-Ready"：现有看板能用，不代表能直接喂给 Agent，需要补主动元数据和语义层。
